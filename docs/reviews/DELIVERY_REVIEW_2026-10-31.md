## 2. P0：必须先修复的数据丢失问题

### P0-01 Windows 同步后继续编辑笔记，内容没有进入保存结果

- **复现**：创建真实 `PaperWindow`，应用远端合并结果，在其实际 `MarkdownTextBox` 中写入新文字，再同步保存到隔离数据目录。
- **结果**：编辑器显示 `local edit after sync`，窗口模型也包含该文字；磁盘保存的仍是 `remote edit`。
- **原因**：控制器把 `State.Papers` 换成合并后的新对象；已有窗口仍持有原来的只读 `_paper` 引用。`SyncUpdateFromPaper` 只是复制字段，没有消除窗口与保存状态之间的对象分离。
- **影响**：界面看起来编辑成功，但保存、重启或后续同步可能丢掉新内容。标题、列表替换及几何变化也需要沿同一引用链检查，不能只修笔记文字。
- **定位**：[AppController.cs:1866](../../AppController.cs)、[PaperWindow.cs:1978](../../PaperWindow.cs)。
- **重新验收条件**：同步后在所有已打开纸片上改标题、正文、待办增删与排序、几何；保存重启和下一轮双端同步均保持结果。大纲打开时也必须更新且不持有过期数据。

### P0-02 手机回传会删除桌面笔记的代码画布内容

- **复现**：C# 序列化含一个代码画布元素和待办分栏宽度的数据；使用项目实际 Dart 模型读取，在手机模型中修改正文、勾选待办，再序列化交给 C# 合并。
- **结果**：代码画布元素从 **1 个变成 0 个**；分栏比例从 `[0.3, 0.7]` 变成默认的 `[1, 1]`。
- **原因**：Dart `PaperData` / `PaperItem` 没有保留这些字段，反序列化后再写出时字段消失；Windows 选择时间较新的手机纸片，将缺失的代码画布当成空内容接受。
- **影响**：手机只改正文也可能使另一类桌面内容消失；不能宣称当前协议“无损双向互通”。
- **定位**：[mobile/lib/models.dart:104](../../mobile/lib/models.dart)、[DataMergeEngine.cs:242](../../DataMergeEngine.cs)。
- **重新验收条件**：定义共享字段、设备本地字段及未知字段的保留规则；用覆盖所有现有字段的同一份样本完成 C# → Dart → C# 和反向往返，未编辑字段不变，确实删除与字段缺失可区分。

### P0-03 手机数据文件损坏后，下一次保存会覆盖可恢复数据

- **复现**：在隔离目录放入截断但仍含笔记文字的 `data.json`，调用实际加载函数，再执行一次普通编辑保存。
- **结果**：加载函数吞掉解析错误并返回欢迎待办；后续保存覆盖原文件，目录中只有这一份新文件，没有恢复副本。
- **原因**：加载失败与首次安装被合并为同一路径；保存直接写入主文件，没有串行写锁、临时文件替换和备份恢复链。
- **影响**：异常退出或写入中断后的可恢复数据会进一步被覆盖。多个未等待的保存调用也需要纳入可靠性整改。
- **定位**：[mobile/lib/sync_service.dart:334](../../mobile/lib/sync_service.dart)、[mobile/lib/sync_service.dart:356](../../mobile/lib/sync_service.dart)、[mobile/lib/main.dart:1983](../../mobile/lib/main.dart)。
- **重新验收条件**：损坏文件原样保留；有明确加载失败或备份恢复状态；保存串行化并使用原子替换；模拟截断、连续写入、进程终止及重启，不能回退成欢迎数据覆盖旧文件。
